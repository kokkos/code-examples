# How to reproduce results from the paper "Performance Improvement of Multi-Dimensional Parallel Loops in Kokkos"

Here we describe instructions for compilation and experiment workflows to obtain the expected results and figures.

## Hardware dependencies

We have tested on the hardware platforms summarized in the table below.
A single node with one GPU or one CPU is sufficient to run the benchmark codes.

## Software dependencies

We rely on the following software dependencies:
- Kokkos [https://github.com/kokkos/kokkos] (fetched automatically)
- Google Benchmark [https://github.com/google/benchmark]
- CMake 3.28.2

## Compilation

We provide a script that configures the benchmark codes.
It creates a build directory, invokes CMake to fetch Google Benchmark and Kokkos, and checks out the relevant Kokkos versions evaluated in this paper.
One sub-build directory is created per version, so that the same benchmarks are compiled against every version presented in this paper, see Table below.
The Kokkos versions for GPU backends are the first four items listed and the versions for CPU backends are the last two.
GPU or CPU should be chosen by passing `--gpu` or `--cpu` as the first option to `configure_all.sh` and `run_platform.sh`.
Kokkos and compiler options must be passed after the `--` separator on the command line.
One should replace the compiler and Kokkos options according to the target platform.

The following commands clone the repository and configure the benchmarks for the Intel PVC platform.

```shell
git clone \
https://github.com/kokkos/code-examples.git
cd code-examples/papers/kokkos-mdrange
./configure_all.sh --gpu --build-dir build \
  -- -DCMAKE_CXX_COMPILER=icpx \
     -DKokkos_ENABLE_SYCL=ON \
     -DKokkos_ARCH_INTEL_PVC=ON
```

Each sub-build directory is then compiled independently, for example, the following command compiles the baseline version for GPU backends.

```
cmake --build build/build_502
```

The following binaries are obtained for both GPUs and CPUs: `bench_mdrange_stencil`, `bench_mdrange_stream`

Mapping between the build sub-directories created by `configure_all.sh` and the Kokkos commit each one is built against and the label used in the figures.
The full commit SHAs are pinned in the top-level `CMakeLists.txt` of the artifact.

| Sub-directory | Commit | Label |
|----|----|----|
|`build_502` | `dfceb772` | Baseline |
|`build_device_iterate` | `7a78e92a` | Refactored     |
|`build_new_tile`       | `c6ab03f3` | New tile size  |
|`build_no_stride`      | `b77b924f` | No grid-stride |
|`build_520` (CPU)      | `e484fccb` | Baseline       |
|`build_auto_vect` (CPU)| `f2cac810` | With-Auto-Vect |

## Evaluation and expected results

Running a benchmark produces a performance profile in JSON format. Achieved bandwidth (GB/s) and kernel run time, are reported by Google Benchmark.
The `run_platform.sh` script runs every benchmark against every variant for a given backend (GPU or CPU) from the above table.
This script takes three arguments: `--gpu`/`--cpu`, the build directory created by `configure_all.sh` and the target platform tag.
The following command writes the profiles to the folders `out_sycl_pvc/stencil_bench` and `out_sycl_pvc/stream_bench`:

```shell
./run_platform.sh --gpu build sycl_pvc
```

Once all the profiles have been collected, the plotting scripts in the `scripts` directory read the JSON files and produce the figures in PNG format.
They require the Python packages listed in `requirements.txt`. Python 3.12 is required for installing a few of the packages with the listed versions.

For GPU backends, the command below generates a figure for stencil benchmark:

```shell
cd out_sycl_pvc/stencil_bench
python3 ../../scripts/plot_gpu_stencil.py \
  sycl_pvc_stencil_502.json \
  sycl_pvc_stencil_device_iterate.json \
  sycl_pvc_stencil_new_tile.json \
  sycl_pvc_stencil_no_stride.json
```

STREAM benchmark Triad plots are generated with the following command:

```shell
cd out_sycl_pvc/stream_bench
python3 ../../scripts/plot_gpu_stream.py Triad \
  sycl_pvc_stream_502.json \
  sycl_pvc_stream_device_iterate.json \
  sycl_pvc_stream_new_tile.json \
  sycl_pvc_stream_no_stride.json
```

In the case of CPU backends, the following command configures the benchmarks for a CPU like AMD EPYC 9654 with OpenMP backend.

```shell
./configure_all.sh --cpu --build-dir build \
  -- -DKokkos_ENABLE_OPENMP=ON -DKokkos_ARCH_NATIVE=ON \
     -DKokkos_ENABLE_AGGRESSIVE_VECTORIZATION=ON
```

Note that enabling aggressive vectorization is not critical.
The number of threads should be passed as the last option of `run_platform.sh`. The figure in Figure~\ref{fig:cpu_t8} was generated by running on 8 threads, with a command as follows:
```shell
./run_platform.sh --cpu build omp_t8 8
```

If number of threads is not passed, a default value of 1 is used.
For the CPU OpenMP backend, the following settings are recommended: `OMP_PROC_BIND=close`, `OMP_PLACES=cores`.
It is also recommended to set `OMP_NUM_THREADS` to a value that is less than or equal to what was passed to `run_platform.sh`.

For the above `run_platform.sh` command, the profiles will be written to the folders `out_omp_t8/stencil_bench` and `out_omp_t8/stream_bench`.
For CPU benchmarks, `plot_cpu_stencil.py` and `plot_cpu_stream.py` are run in the same manner as it is done for GPU backends, with the appropriate JSON files.
The comparisons are between the files ending as `_520.json` and `_auto_vect.json`.

For the above `run_platform.sh` command, the following command generates a figure combining results from stencil and STREAM benchmarks:

```shell
cd out_omp_t8
python3 ../scripts/plot_cpu_stencil_stream.py \
  stencil_bench/omp_t8_stencil_520.json \
  stencil_bench/omp_t8_stencil_auto_vect.json \
  stream_bench/omp_t8_stream_520.json \
  stream_bench/omp_t8_stream_auto_vect.json \
  Baseline With-Auto-Vect Triad
```

To generate a figure to plot performance for increasing number of threads, one needs to run the benchmarks for different numbers of threads (1, 2, 4, 8, 16, 32). To start with, the following commands are run: `./run_platform.sh --cpu build omp_t1`, `./run_platform.sh --cpu build omp_t2 2`, ..., `./run_platform.sh --cpu build omp_t32 32`.
A file `info_file.txt` shown in `plot_cpu_scale.py` needs to be prepared with the input information.
Then, the following command generates the required figure:

```shell
cd scripts
python3 plot_cpu_scale.py info_file.txt
```
